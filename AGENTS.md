# AGENTS.md

This is the website for the scientific journal **"Izvestiya vuzov. Yadernaya Energetika"** (Nuclear Power Engineering), ISSN 0204-3327. It is a bilingual (Russian + English) static site built with **Hugo v0.101.0**, containerized with Docker, and deployed via GitHub Actions.

## Build & Deploy

### Local build (requires Hugo v0.101.0)

```bash
# Build English site first (outputs to public/en)
hugo --minify --theme npe --config=config_en.toml --destination=public/en
# Build Russian site (outputs to public/)
hugo --minify --theme npe --config=config.toml --destination=public
```

**Important**: The English build must run first because it outputs to `public/en`, and the Russian build outputs to `public/`. Running them in the wrong order would overwrite the English output. This is exactly how the Dockerfile does it.

There are no tests, no linter, and no package manager — Hugo runs directly from a binary.

### Docker build

```bash
docker build -t npe .
```

The Dockerfile uses a multi-stage build:
1. Alpine + Hugo binary builds both language versions into `/tmp/site/public`
2. Static files are copied into a `ghcr.io/umputun/reproxy` container serving from `/srv/site`

### CI/CD (`.github/workflows/docker-build-and-push.yaml`)

- Triggers on push to `develop` branch
- Builds Docker image and pushes to `ghcr.io/nuclear-power-engineering/nuclear-power-engineering`
- After push, triggers deployment via `curl` to `update.nuclear-power-engineering.ru/update/website/`
- The `updater` container (defined in `docker-compose.yml`) pulls and restarts the website container via SSH

### Runtime (docker-compose.yml)

The production stack runs on the server:
- **website**: The static site served by reproxy (ports 80/443, auto SSL via ACME)
- **updater**: Listens for webhooks to pull and restart the website container
- Static assets (PDFs, images) are served from a separate CDN: `static.nuclear-power-engineering.ru` (Selectel CDN)

## Architecture & Data Flow

The site has **no backend** — it is entirely static HTML generated by Hugo. Two separate Hugo builds produce the Russian and English sites.

### Key Hugo concepts

- **Taxonomies**: `issue`, `authors`, `tags`, `rubric` — defined in both configs
- **Content sections**: `article` (individual articles), `full-issue` (complete journal PDFs), `issue` (issue index pages with cover images)
- **Data files**: Author profiles in `data/authors/*.toml` and `data_en/authors/*.toml` are accessed in templates via `.Site.Data.authors`
- **DOI XML**: English articles use `outputs=["HTML", "DOI"]` to generate Crossref DOI deposit XML via `layouts/article/single.xml`

### URL structure

- Russian: `/{section}/{slug}/` (e.g., `/article/2026/01/01/`)
- English: `/en/{section}/{slug}/`
- Issue archive: `/issue/YYYY-MM/` (e.g., `/issue/2026-01/`)
- Author pages: `/authors/{term}/` where term is the author ID (e.g., `/authors/KaluginMA/`)
- Rubric pages: `/rubric/{rubric-slug}/`
- Full issue PDFs: `/full-issue/YYYY-MM/`

### Language switching

The header template constructs cross-language links by manipulating `{{.Permalink }}` — Russian pages link to `/en/` + same path, English pages strip the `/en/` prefix.

## Content Format

### Article front matter (Russian — `content/article/YYYY/MM/NN.md`)

```toml
+++
categories="article"
date="2026-03-27T00:29:00+03:00"
issue="2026-01"
issue_name="2026 - №01"
number="01"
file="https://static.nuclear-power-engineering.ru/articles/2026/01/01.pdf"
doi="https://doi.org/10.26583/npe.2026.1.01"
udc="621.039.51"
first_page="6"
last_page="15"
rubric="currentissues"
rubric_name="Актуальные проблемы ядерной энергетики"
title="Article title in Russian"
authors=["AuthorTerm1", "AuthorTerm2"]
tags=["tag1", "tag2"]
+++
```

### Article front matter (English — `content_en/article/YYYY/MM/NN.md`)

English articles have **two additional fields** that Russian articles do not:

```toml
outputs=["HTML", "DOI"]
issue_id="1"              # Numeric issue number (for DOI XML generation)
original_title="Russian title here"  # Original Russian title
```

The `issue_name` format also differs: `"2026 - #01"` (hash) vs `"2026 - №01"` (№ sign).

### Article `00.md` — Editor's column

Each issue may have a `00.md` file which is the editor's column. It has no `authors`, `doi`, `udc`, or `number` fields — just `rubric="editors"`.

### Issue index (`content/issue/YYYY-MM/_index.md`)

These are empty files — the issue page template (`layouts/taxonomy/issue.html`) pulls its data from the articles in that issue and the `cover.png` page bundle resource.

### Full-issue pages (`content/full-issue/YYYY-MM.md`)

```toml
+++
categories = "full-issue"
file = "https://static.nuclear-power-engineering.ru/journals/2017/02.pdf"
issue = "2017-02"
issue_name = "2017 - №02"
weight = 0
title = "Полный номер журнала №2 за 2017 год"
+++
```

### Author TOML files (`data/authors/AuthorTerm.toml`)

```toml
term="AdamovEO"
name="Е.О. Адамов"
work="АО «Прорыв»"
full_name="Адамов Евгений Олегович"
regals="научный руководитель проектного направления «Прорыв»"
email="slp@proryv2020.ru"
```

The **filename** and **term** value must match exactly and follow the pattern: `Surname` + first letter of first name (uppercase) + first letter of patronymic (uppercase) — e.g., `KaluginMA` for "Михаил Анатольевич Калугин".

English files (`data_en/authors/`) use the same term/filename but English values:

```toml
term="AdamovEO"
name="Adamov E.O."
work="JSC Proryv"
full_name="Adamov Evgeny Olegovich"
regals="Scientific Director of the Project Direction «Proryv»"
email="slp@proryv2020.ru"
```

The `full_name` format is **"Surname FirstName Patronymic"** (not "FirstName Surname") in both languages. The template uses `full_name` to construct citation strings by extracting initials.

## Helper Scripts

All Python scripts are run manually. They have hardcoded values that must be edited before each use.

### `new-articles.py`
Creates stub article files for a new issue. **Must edit** the `year`, `date`, `issue_number`, and article count range in `main()` before running. Creates both RU and EN stubs with correct front matter.

### `new-author.py`
Creates a new author TOML file pair (RU + EN). **Must edit** `raw_work_ru`, `raw_author_ru`, `raw_work_en`, `raw_author_en` at the top of the file with the author's full info string. The term/filename is auto-generated from the English name.

### `new-journal.py`
Creates an issue directory with cover image. Takes 3 CLI arguments:
```bash
python3 new-journal.py <input_file.pdf> <year> <issue_number>
```
Crops the right half of the PDF's first page as the cover image. Requires `fitz` (PyMuPDF) and `Pillow`.

### `fix-full-authors.py`
Fixes English author TOML files where `full_name` is in "FirstName X. Surname" format instead of the correct "Surname FirstName X." format. Operates on `data_en/authors/`.

## Key Gotchas

1. **Hugo version is pinned to v0.101.0** — do not upgrade without testing. The Dockerfile downloads a specific release binary.

2. **Two separate Hugo builds** — Russian and English are independent builds with different configs, content dirs, data dirs, and output dirs. They are not a multilingual Hugo site; they are two separate sites that happen to share a theme.

3. **English build runs first** in the Dockerfile — this ordering matters because both output under `public/`.

4. **Article numbering**: `number` field uses zero-padded two-digit format (`"01"`, `"02"`, etc.) in newer articles. Older articles use bare integers (`"1"`, `"2"`). The template uses `number` to prefix article titles in issue listings.

5. **`authors` array references by term** — the `authors` field in articles is an array of author term strings (e.g., `["KaluginMA"]`), not display names. These must match exact TOML filenames (without extension) in `data/authors/`.

6. **PDF files are external** — article PDFs and full-issue PDFs are hosted on a CDN at `static.nuclear-power-engineering.ru`, not in this repo. The `file` field is a full URL.

7. **DOI format**: `10.26583/npe.{year}.{issue}.{article:02d}` — e.g., `10.26583/npe.2026.1.01`

8. **Date format in front matter**: Uses Hugo's TOML datetime format with Moscow timezone offset `+03:00`. The `new-articles.py` script generates minutes as `(30 - article_number)` to keep dates unique per article.

9. **`issue_name` format differs**: Russian uses `№` (№01), English uses `#` (#01).

10. **Template uses `.Site.Data.authors` as a map** — templates iterate over all author TOML files to find matches. The key in this map is the filename without extension (the term).

11. **The `config_en.toml` defines a custom output format `DOI`** for generating Crossref XML — this is only used by English articles.

12. **Menu "For readers > The latest issue"** must be manually updated in both `config.toml` and `config_en.toml` when a new issue is published (change the URL to `/issue/YYYY-MM/`).
